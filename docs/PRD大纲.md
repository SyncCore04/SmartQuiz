## 2. 产品概述

### 2.1 产品背景
- 痛点：练习题目分散、对答案费时、错题无沉淀、学习效果不可量化。
- 机会：微信小程序即点即用，适合轻量刷题场景。

### 2.2 产品定位
- 一句话定位：面向学生的**轻量级在线刷题与模拟考试小程序**，主打「答题自动判分 + 错题自动沉淀 + 学习数据可视化」的闭环体验。
- 产品形态：微信小程序（客户端）+ HTTP API（服务端）+ SQLite（存储）。

### 2.3 产品价值与亮点
- 价值主张：把「练 → 判 → 错 → 析 → 统计」全流程搬到线上，秒级出分。
- 差异化亮点（答辩/评审视角）：
  1. 判分在服务端完成，题目接口不下发答案，防作弊；
  2. 错题在提交判分时自动收集，无需手动录入；
  3. 统计（正确率、连续打卡、周答题柱状图）实时反映真实答题记录。

### 2.4 名词解释
- 题库（bank）/ 考试（exam）/ 错题本（wrong_item）/ 游客登录 / 题型 key（single/multi/judge/fill）等。

## 3. 目标用户与场景

### 3.1 目标用户画像
- 主要用户：初高中/大学学生，碎片时间刷题、考前模拟。
- 次要用户：答辩评审/教师（验证功能闭环）。

### 3.2 核心使用场景（用户故事）
1. 作为学生，我想按学科分类找题，快速开始练习；
2. 作为学生，我想提交答卷后立刻看到分数和逐题对错解析；
3. 作为学生，我希望做错的题自动进入错题本，方便回顾并删除已掌握的题；
4. 作为学生，我想看到正确率、连续打卡天数、本周答题量，量化学习效果；
5. 作为学生，我想参加带状态（进行中/未开始/已结束）的模拟考试。

### 3.3 使用环境
- 微信开发者工具（本地演示）或微信真机；后端运行于本机/局域网（127.0.0.1:5000）。

## 4. 产品目标与成功指标

### 4.1 产品目标
- 课程目标：完成可运行、可演示、可讲解的前后端联动项目，验证功能闭环。

### 4.2 成功指标（可量化验收）
- 核心闭环通过率：登录 → 答题 → 判分 → 错题 → 统计，全链路 100% 可跑通；
- 判分准确率：与人工核对一致；
- 接口响应：本地环境下接口响应 < 1s；
- 数据一致性：提交后统计页/错题本/记录页数据与刚才作答完全对应。

### 4.3 范围外（Non-goals）
- 真实支付、社交分享裂变、教师后台出题系统、大规模并发与分布式部署。

## 6. 功能需求详述（按模块）

> 每个模块建议按「功能描述 / 交互流程 / 字段与规则 / 异常与边界」四段展开。以下给出要点与本项目对应接口。

### 6.1 用户模块
- 功能描述：游客登录，按昵称幂等创建/复用用户，返回 `user_id`。
- 对应接口：`POST /api/login`（`{nickname}` → `{user_id, nickname}`）。
- 规则：昵称为空默认「学长」；前端本地缓存登录态（`smartquiz_user`），每次操作前 `ensureUser()` 幂等刷新。
- 异常：请求失败时提示「请求失败」。

### 6.2 首页模块
- 功能描述：轮播图（swiper）、学科分类宫格（含题数）、热门题库横向卡片区。
- 对应接口：`GET /api/swipers`、`GET /api/categories`、`GET /api/banks`。
- 规则：分类图标/配色随数据返回；题库展示题量与标签（热门/推荐/新课）。

### 6.3 题库与题目列表
- 功能描述：按分类进入题目列表；列表支持按题型筛选（单选/多选/判断/填空）。
- 对应接口：`GET /api/questions?category_id=&type_key=&bank_id=`。
- 规则：**返回不含 answer/analysis**（安全要求）；字段含 `num/type/typeKey/difficulty/title/options`。
- 异常：空列表展示占位。

### 6.4 答题与判分模块（核心）
- 功能描述：逐题作答（单选互斥、多选可切换、判断二选一），支持题号导航，一键提交。
- 对应接口：`POST /api/submit`（`{user_id, title, time_used, answers:[{question_id, my_answer}]}`）。
- 判分规则：
  1. 答案比对忽略大小写；多选为排序后的字母组合（如 `AC`）；
  2. `score = round(正确数 / 总数 × 100)`；
  3. 写入 `user_record` 一条记录；错题写入/更新 `wrong_item`（同一题以题干判重，更新「我的答案」而不重复插入）。
- 返回：`{score, total, correct, wrong, accuracy, timeUsed, results[]}`（逐题对错与标准答案）。
- 异常：缺 `user_id` 返回 `code=1`；题目不存在则跳过该题。

### 6.5 结果页模块
- 功能描述：展示得分、正确/错误数、正确率、用时；逐题回看（我的答案 vs 正确答案 + 解析）。
- 数据来源：`/api/submit` 返回结果（经本地缓存 `last_submit` 传递）。

### 6.6 考试模块
- 功能描述：考试列表（封面/日期/时长/题量/参与人数/状态标签），考试详情（含 `questionIds`）。
- 对应接口：`GET /api/exams`、`GET /api/exams/<id>`。
- 规则：状态 ∈ 进行中/未开始/已结束，状态色随数据返回。
- 规划（P1）：倒计时、到点强制交卷。

### 6.7 错题本模块
- 功能描述：错题列表（题干、我的答案、正确答案、解析），支持删除单条错题。
- 对应接口：`GET /api/wrong-book`、`DELETE /api/wrong-book/<id>`。
- 规则：按收集时间倒序；删除不存在的错题返回失败提示。

### 6.8 学习统计模块
- 功能描述：累计答题数、正确率、连续打卡天数、本周（周一~周日）每日答题柱状图。
- 对应接口：`GET /api/stats/overview?user_id=`。
- 规则：连续天数=从最近有记录日期向前连续（日差 1 天）的段长；柱高按本周最大值归一化，由后端计算后返回。

### 6.9 我的模块
- 功能描述：头像昵称展示、答题数/正确率/连续天数统计卡。
- 对应接口：`GET /api/profile?user_id=`。

## 7. 业务流程

### 7.1 核心业务流程（答题闭环）
用户进入答题页 → 拉取题目（无答案）→ 作答 → ensureUser → 提交 → 服务端判分 → 写答题记录 → 错题入库 → 返回成绩单 → 查看结果 → 统计/错题本实时更新。

### 7.2 状态机
- 考试状态：未开始 → 进行中 → 已结束（由种子数据维护展示）。
- 登录态：未登录 → 登录成功（缓存 user_id）→ 幂等续期。

### 7.3 页面导航关系
TabBar 三页（首页/考试/我的）+ 二级页（分类 → 题目列表 → 答题 → 结果；考试列表 → 考试详情；错题本、统计入口）。

## 8. 数据需求

### 8.1 实体关系（ER）
- `user 1:N user_record / wrong_item`；
- `category 1:N question`；
- `bank N:M question`（中间表 `bank_question`）；
- `exam N:M question`（中间表 `exam_question`）；
- 辅助表：`swiper`（轮播）。

### 8.2 核心表字段
- `question`：id、category_id、type、type_key、difficulty、title、options_text、answer、analysis；
- `user_record`：id、user_id、title、score、total、correct、wrong、date；
- `wrong_item`：id、user_id、num、title、my_answer、correct_answer、analysis、created_at。
- 完整建表语句见 `backend/app.py` 的 `SCHEMA`。

### 8.3 数据初始化与维护
- 题库统一维护在 `backend/questions_data.py`（19 题，四学科，四种题型）；首次启动自动建库灌数；加题需删库重启（演示策略）。

## 10. 非功能需求

### 10.1 性能
- 本地单机演示，接口毫秒级返回；统计计算在服务端完成，避免前端循环求和。

### 10.2 安全
- 题目接口不下发答案与解析，判分仅发生在服务端；
- 全部数据库操作使用参数化 SQL（`?` 占位），防 SQL 注入；
- 规划项：token 鉴权、接口频控。

### 10.3 兼容性与可用性
- 微信开发者工具 + 真机（局域网 IP 访问后端）；开发者工具需关闭域名校验；
- 重启不丢数据（`init_db` 仅在空库时建表灌数）。

### 10.4 可维护性
- 题库与代码分离（`questions_data.py` 独立数据文件）；
- 接口统一响应格式与统一请求封装（`front/utils/api.js`），降低前后端联调成本。

## 12. 风险与开放问题

### 12.1 风险
- 评审环境无 Python/网络：准备演示视频或截图；
- 本地服务未启动导致前端无数据：启动前检查 5000 端口；
- 加题后旧库不更新：需删除 `smartquiz.db` 重启（文档已注明）。

### 12.2 开放问题
- 多选部分正确是否给分（当前全对才得分）？
- 是否需要教师端出题/组卷后台？
- 真实上线时跨域头与鉴权策略如何收紧？
